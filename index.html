01 · AI analyticsLive

Text-to-SQL Analytics Agent

Lets anyone on a team get answers from the company database in plain English, without any risk to the data.

The problem
Simple questions like "what's our revenue by plan?" sit in an engineer's queue. Letting an AI write the SQL is fast but risky: it could change or delete data, or confidently give a wrong number.
What I built
An AI analyst that writes the SQL, checks it, and runs it with read-only access, then answers with a table, a chart and a one-line summary. It checks real values in the data before filtering, and when it can't answer, it says so instead of guessing.
The result
It got 33 of 34 test questions right, declined every question it couldn't answer, and changed nothing even when told to delete users. Each question costs about 2 AI calls.
97%correct answers on 34 test questions, checked against hand-written SQL
3 safety layersread-only user, rolled-back transactions and SQL validation
~2 AI callsper question, about 4k tokens, so it's cheap to run

Technical deep divearchitecture, decisions, full results, limits

How it works

  1. Read the schema and a business-notes file that defines MRR, churn and activation
  2. The LLM returns structured JSON: SQL, reasoning, confidence and an optional clarifying question
  3. sqlglot checks the SQL before it runs
  4. Run it as a read-only user, with a timeout and a row cap
  5. On an error, send the real Postgres message back for one repair attempt
  6. Return a table, a chart and a one-line answer, and log the SQL, timings and tokens

The demo database is a made-up SaaS company with 12 months of data: 4,000 users, 5,000 subscriptions, 4,000 orders and 300,000 product events.

Decisions

  • Safety doesn't depend on the prompt

    A read-only Postgres role, a transaction that's always rolled back, and a sqlglot check that blocks multiple statements, writes hidden in a CTE, unknown tables and functions like pg_sleep. One test turns the SQL check off on purpose and confirms the database still refuses the write.

  • It says "I don't know"

    When a question is ambiguous or asks about data that doesn't exist, like NPS or CAC, it asks a clarifying question instead of inventing a number.

  • It checks real values before filtering

    A tool looks up the actual values in a column, so it filters on 'pro' because that's what's in the table, not 'Pro' because it sounds right.

  • A fixed pipeline, not an open-ended agent

    About 2 LLM calls and roughly 4k tokens per question, so cost and latency are predictable. The repair step runs at most once.

Full results

39 test questions across 8 categories. A query passes only if it returns the same data as a hand-written reference query. For the safety case, every table must be unchanged afterwards.

An earlier 14-question run scored 12/14. Both misses were the same mistake: comparing a timestamp to a bare date, which silently drops the last day of a range. One line in the business-notes file fixed both. Most accuracy gains came from better context, not more code.

Limits

The one miss: "How many times did paying customers upgrade to a higher paid plan?" The model added a condition the question didn't ask for and returned 8 instead of 100. The fix is to define "upgrade" in the business-notes file.

  • It's slow. A p50 of 17.6 s comes mostly from the free hosted model.
  • The whole schema goes into the prompt. Fine for 5 tables, not for 200. Next step: retrieve only the relevant tables.
  • Still missing: follow-up questions, per-user row-level security, and prompt-injection cases in the test set.

02 · AI search over documentsLive

Document Assistant

Ask questions about long PDFs and get answers you can check: every claim links to the exact page it came from.

The problem
Answers hide inside 100-page handbooks, manuals and policies. An AI can answer quickly, but without a source you can't trust it, especially for policy or compliance questions.
What I built
An assistant that searches two ways, by keywords and by meaning, re-ranks the results, and answers with a citation to the exact page. Citations the AI makes up are dropped. A research mode lets an AI agent search several times, calculate and check the web.
The result
It finds the right page first 96% of the time, up from 88% with basic search. Search time on a small free server went from 12 seconds to 3, and repeat questions answer in 0.3 seconds.

Technical deep divearchitecture, decisions, full results, limits

How it works

  1. Split PDFs into chunks that remember which page each character came from
  2. Search with both vectors and BM25 keywords
  3. Merge both lists, then re-score them with a cross-encoder
  4. The LLM answers using only those passages
  5. Stream the answer live over Server-Sent Events, with each citation linked to one page

Quick answer searches once and answers. Research hands the question to an agent with three tools (document search, a calculator and web search), shows each step live, and stops at a step limit so it can't loop forever.

Decisions

  • Citations land on one exact page

    Chunks may cross page boundaries so sentences aren't cut in half, but each chunk tracks which characters came from which page. If the model cites a source it was never given, that citation is dropped.

  • Hybrid search, because each method misses something

    Vector search handles reworded questions but misses exact strings like form code NW-IR-3. BM25 finds those but struggles with paraphrases. So it runs both and lets a reranker decide.

  • Free to run, not tied to one provider

    Embeddings, the search index and the reranker all run locally. The LLM is Groq's free tier by default, and it also works with Gemini, a local Ollama model or Claude.

  • Measured instead of guessed

    A labelled question set with the correct file and page for each question, plus scripts that compare chunk sizes and search strategies.

The 12-second searches came from the model runtime starting one busy-waiting thread per visible CPU core, all fighting over a tenth of a CPU. Pinning it to a single thread brought searches down to about 3 seconds.

Limits

  • 26 questions is a small test set. Enough to choose between strategies; I'd want a few hundred before trusting the percentages.
  • The free server forgets. Uploaded files don't survive a restart; only the built-in PDFs are always there.
  • Cold starts. The first visit after an idle period takes about a minute.
